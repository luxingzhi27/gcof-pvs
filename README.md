# GCOF-PVS

Python implementation of geometry-compiled occlusion fields for regional
visibility prediction. The shared model compiles instance geometry and
geometry-only relations into compact direction-dependent fields, then scores
candidate instances from a camera-relative view-cell query.

## Install

The reference setup uses Python 3.11 and PyTorch 2.5.1 with CUDA 12.1.

```bash
conda create -n gcof-pvs python=3.11 pip
conda activate gcof-pvs
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -e .
```

## Prepare Data

The commands use `data/` by default. Use `--data-root` to keep data elsewhere.
The [scene registry](src/gcof_pvs/data/scene_registry.json) declares the five
real scenes, camera settings, and frozen split counts. Supply a different
`--registry` to map the same protocol onto another directory layout; its
paths are relative to the data root.

```text
data/
  scenes/<scene-id>/pose_csr/        # dataset_meta.json and CSR arrays
  scenes/<scene-id>/assets/          # runtimeVisibilityMeta.json and glbIndex.json
  compiled/<scene-id>/surface/      # local surface samples
  compiled/<scene-id>/relation/     # geometry-only directional relation graph
  synthetic/<scene-id>/             # generated by gcof-synthetic
```

Real-scene data and trained checkpoints are separate inputs. The Python
utilities under [preprocessing](src/gcof_pvs/preprocessing/) convert
existing regional visibility samples to PoseCSR and prepare or apply split
manifests. The procedural dataset generator creates 120 scenes; the shared
trainer reads only the 96 synthetic training scenes and the real train splits.

```bash
gcof-synthetic --all --output-root data/synthetic --device cuda
ulimit -n 65536
gcof-train preflight --protocol shared --output runs/preflight.json
```

## Train

```bash
gcof-train train --protocol shared --variant FULL --seed 0 \
  --real-updates-per-scene 36000 --checkpoint-every 9000 \
  --device cuda --output-dir runs/full_seed0
```

The shared schedule interleaves two real-scene updates with one procedural
update, for 270,000 updates at the paper budget. Each run writes its config,
step metrics, and checkpoints. Resume with the same run arguments and
`--resume runs/full_seed0/checkpoint_last.pt`.

Run each ablation with the same data and schedule by replacing `--variant`
and using a different output directory:

| Variant | Change relative to FULL |
| --- | --- |
| `GEOMETRY_FIELD` | Compile the structured field from instance geometry without relation edges. |
| `GENERIC_RELATION_28` | Replace the structured field with a 28-dimensional relation latent. |
| `PBCE_OBJECTIVE` | Keep the full architecture and use pose-balanced binary cross-entropy. |

## Evaluate

Export scores from a trusted checkpoint, then evaluate the scores without
updating the model. The paper's shared models use a fixed logit threshold of
zero. The commands below evaluate validation only.

```bash
gcof-eval export --checkpoint runs/full_seed0/checkpoint_last.pt \
  --output-dir runs/full_seed0_scores --device cuda
gcof-eval evaluate --protocol shared --fixed-zero --split validation \
  --bundle runs/full_seed0_scores/manifest.json --output runs/full_seed0_validation.json
```

For final test after model selection, export into a separate directory with
`--final-test`, then evaluate that bundle with `--split test --final-test`.

## Code Map

| Package | Responsibility |
| --- | --- |
| `gcof_pvs.data` | Read PoseCSR, validated scene assets, and shared camera query inputs. |
| `gcof_pvs.data.synthetic` | Generate layouts, ray-cast labels, and serialize procedural scenes. |
| `gcof_pvs.model` | Encode local geometry, compile directional relations, and score instances. |
| `gcof_pvs.training` | Sample source scenes, optimize the objective, and save or resume runs. |
| `gcof_pvs.evaluation` | Export frozen scores and report regional set metrics, including weighted recall and CNOR. |

Run the CPU contract tests with `python -m unittest discover -s tests`.
